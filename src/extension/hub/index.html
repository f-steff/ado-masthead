About Masthead

Version loading...

Use General to set the organization master switch and the defaults used when new projects and repositories are discovered. The project table lets an organization administrator disable reviews for one project without changing its repository settings.

Use Setup to choose event delivery, identify the central review pipeline, and validate that the pipeline is readable by the current identity.

Use Review profile to choose the default provider, model, reasoning options, lenses and review guide. Model suggestions come from the separate hourly catalogue pipeline and remain editable for custom names. Projects and repositories can inherit or override provider and lens choices. Use Examples to preview the input and expected output for every lens.

Repository-level switches live under each project's Project settings > Masthead page. A pull request is reviewed only when the organization, project and destination repository are all enabled. This also applies when the PR originates from a fork or another project: the destination repository supplies the gate.

Provider keys are never entered in this browser page. Keep the provider key in an Azure DevOps secret variable group linked only to the central review pipeline.

By default, comments use the pipeline's build-service identity. To show a dedicated review identity, create a service account and supply its short-lived PAT as the secret MASTHEAD_ADO_TOKEN; do not use your personal daily PAT.

Automatic event delivery, deployment of a trusted pipeline repository/YAML, PR-tab publication and branch-policy completion gating are still being built. The worker now reads these settings before spending tokens.
